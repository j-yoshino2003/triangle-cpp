# RenderDoc の導入と使い方

このプロジェクトのフレームをキャプチャして、描画結果とパイプラインの状態を調べるための
手順です。インストールはユーザーが実行します（Claude はインストーラーのダウンロードと実行を
行いません）。

## このプロジェクトに必要な変更はありません

RenderDoc は Vulkan 標準のレイヤー機構を使います。RenderDoc から実行ファイルを起動すると、
環境変数を立てた状態でプロセスを起こし、Vulkan ローダーが RenderDoc のレイヤーを読み込みます。
**`cpp.vcxproj` の設定変更もコードの変更も不要**です。

レイヤーは Windows のレジストリに登録されている必要がありますが、MSI インストーラーが登録まで
行います。ZIP 版を展開して使う場合は、キャプチャ用のパネルに「レイヤーの登録が必要」という警告が
出るので、その警告をクリックすると登録されます。

## 1. インストール

現行の安定版は **v1.46**（2026 年 8 月 31 日リリース）です。64 ビット版だけ入れれば足ります
（このプロジェクトは x64 のみの構成です）。

| 配布形式 | ファイル | URL |
| --- | --- | --- |
| インストーラー（推奨） | `RenderDoc_1.46_64.msi` | https://renderdoc.org/stable/1.46/RenderDoc_1.46_64.msi |
| ZIP | `RenderDoc_1.46_64.zip` | https://renderdoc.org/stable/1.46/RenderDoc_1.46_64.zip |

配布元の一覧は https://renderdoc.org/ にあります。MSI の方がレジストリへのレイヤー登録を
自動で済ませるため、特に理由がなければこちらを使ってください。

## 2. このプロジェクトを RenderDoc から起動する

1. RenderDoc を起動する
2. **File** → **Launch Application**
3. **Executable Path** に `C:\Triangle\cpp\x64\Debug\cpp.exe` を入れる
   - **Working Directory** は空のままでよい（実行ファイルのあるフォルダーが既定で使われる）
   - シェーダーは `x64\Debug\shaders\` に出力されるので、作業ディレクトリが実行ファイルの隣で
     あることが前提になる
4. **Launch** を押す

毎回入れ直すのが面倒なら、**Save** で実行ファイル・作業ディレクトリ・コマンドラインを `.cap`
ファイルに保存できます。**Auto start** を有効にしておくと、その `.cap` を開いた時点で起動します。

## 3. キャプチャする

- 起動したアプリの画面に RenderDoc のオーバーレイが出る。これが出ていれば RenderDoc が
  読み込まれている
- **F12** または **Print Screen** を押すと、**その次のフレーム**がキャプチャされる
- アプリを終了すると、キャプチャしたフレームが RenderDoc の UI で自動的に開く。1 つも
  キャプチャしていなければ、UI は Launch 前の状態に戻る
- 複数キャプチャした場合はサムネイル一覧から選んで開く。別インスタンスで開けば並べて比較できる。
  アプリが動いている間でも **Capture Connection** から同じ一覧に届く

## 現時点ではまだキャプチャできません

RenderDoc がキャプチャする単位は**フレーム**で、フレームの区切りは画面への表示
（`vkQueuePresentKHR`）で決まります。現在の `src\main.cpp` は GLFW と Vulkan のバージョンを
表示して終了するだけで、ウィンドウもスワップチェーンも作っていないため、**区切るフレームが
存在しません**。

RenderDoc が効くのは、スワップチェーンを作ってフレームループを回すようになってからです。
インストールだけ先に済ませておき、使うのは実装が進んでからになります。

## 検証レイヤとの関係

三角形が出ない段階で最初に頼るのは RenderDoc ではなく**検証レイヤ**です。

| 症状 | 使う道具 |
| --- | --- |
| API の使い方が間違っている | 検証レイヤ（`VK_LAYER_KHRONOS_validation`）がメッセージで指摘する |
| 検証レイヤは黙っているが画面が真っ黒 | RenderDoc。ドローコールが発行されているか、パイプライン状態と頂点出力を見る |
| ドライバーや SDK 自体が怪しい | Vulkan SDK 同梱の `vkcube.exe` で切り分ける |

検証レイヤもレイヤー機構で読み込まれるので、RenderDoc と同じ枠組みに乗っています。どのレイヤーが
有効になっているかは Vulkan SDK 同梱の `vkconfig-gui.exe`（`C:\VulkanSDK\1.4.357.0\Bin\`）で
確認・変更できます。

> **未着手**: 検証レイヤの有効化と、メッセージを受け取るデバッグメッセンジャーの作成は
> コード側の作業で、まだ入っていません。実装段階の最初に入れます。
