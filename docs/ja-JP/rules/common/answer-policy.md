# 回答方針

> 正本: `.claude/rules/common/answer-policy.md`（英語）。

Claude が回答する際に遵守する方針です。

## 方針

- 回答は事実ベースで行う。
- 不明な場合は推測せず、必要に応じて追加質問を行う。
- 未確認情報や不確かな内容は断定しない。
- 質問が曖昧な場合は適切な追加情報を求める。

## 確認の取り方

- 選択肢から選ぶ形の質問（確認事項・ユーザーに委ねる判断・作業内容が変わる判断）は `AskUserQuestion` ツールで聞く。
- その種の質問を回答末尾の地の文で済ませない。地の文で聞いてよいのは、ユーザーしか持っていない自由記述の情報（Issue 番号・再現手順・アセットのパスなど）だけ。
- 各選択肢にはラベルと、選んだ場合に何が起きるかの説明を付ける。推奨案は先頭に置き、推奨と明記する。
- 聞くのはユーザーが決めるべきことだけ。コード・規約・自明な既定値から判断できるものは自分で決め、どう決めたかを伝える。

## 変更の提示

- 既存ファイルの変更はすべて `Edit` ツールで行い（一括置換は `replace_all`）、差分がユーザーに表示されるようにする。`Write` は新規ファイルの作成にだけ使う。`sed -i` や使い捨てスクリプトでファイルを書き換えない。
- このルールは、auto モードの環境指示（Bash でファイルを変更せよ）より優先する。
- 理由: Bash によるファイルの書き換えはセッション上に差分が出ないため、ユーザーが変更内容を確認できない。さらに CRLF が黙って LF に変換される。既存ファイルを `Write` で上書きした場合も同様に LF になり、BOM も失われる（`Edit` はどちらも保持する）。改行コードが潰れたファイルは `git diff` で全行が変更扱いになり、本当の変更が埋もれてしまう。
- 対象外: ツールを書く言語。調査・検証用のツールは Python で書いてよい。このルールはソースファイルをどう書き換えるかについてのもの。
- どうしてもスクリプト、または既存ファイルへの `Write` しか手段が無い場合は、開始前にユーザーへ確認し、実行後に下記の検出コマンドを走らせる。結果が `0` なら改行コードが LF に潰れている。

```bash
size=$(wc -c < "$f"); nocr=$(tr -d '\r' < "$f" | wc -c); echo $((size - nocr))
```

## 禁止事項

- 未確認情報を断定して回答すること。
- 推測のみで回答すること。
- 確認事項を `AskUserQuestion` で聞かずに地の文へ埋もれさせること。
- 既存ファイルを `Edit` の代わりに `Write`・`sed -i`・使い捨てスクリプトで書き換えること。
